# 训练过程的源图机制证据

这里记录“取了哪里、参照什么、为何给予贡献、实际如何汇总”。预测框好坏提供检测结果；机制图必须展示上述中间过程。

## 固定采集规则

- **群体子集：** seed=20260913，从完整 9,156 张训练图均匀无放回抽取 96 张；记录这些图的全部 Hungarian 关联对象及最高类别分数的 20 个额外查询。统计单位要写清为随机图像内的对象，不能宣称均匀抽取了所有对象。
- **解释图例：** 每类按对象面积分成两个等数量层，各以固定哈希选一个对象，共最多 16 个。选择与模型分数、人工可见性、成功与否无关；稀缺层留空而不伪造。
- **时间点：** 初始化，以及完成 1、5、10、15、20 轮；文件夹 `epoch_0000` 表示完成第 1 轮。
- **身份关联：** 固定图像与 GT 索引，每个时间点重新用 matcher 关联查询。query 编号不代表跨轮固定对象。低分、错误类和未关联对象保留。
- **模型状态：** 使用评估所用 EMA（未启用 EMA 时用 model）。单独对固定训练子集做 eval 前向；不使用训练 DN；前向只传图像和有效区域掩码。GT 仅在前向后用于身份关联。
- **隔离：** 主进程采集，其他 DDP rank 在轮末等待；恢复模型各层训练状态和随机数状态。其耗时单独记录，不混入网络推理速度。

采集规则保存为 `diagnostics/source_evidence/panel.json`。五种方法必须共用同一规则。它用于解释机制，不代替 4,885 张官方测试图的 AP。

## 图和数值

每个阶段的 `index.html` 汇集预先选定的图例。每个对象有两张 PNG：

1. **八波段原图。** 同一空间裁剪、固定 [0,1] 灰度；标注轮廓只用于确认对象。保留实际波段坐标，不纠正错位，也不假设轮廓内全是目标像素。
2. **机制图。** 原 B4、实际进入背景估计的网格与权重、语义 attention、背景相对分数、对象兼容性、实际贡献。背景分数固定 [-4,4]，兼容性与背景权重固定 [0,1]；attention 与贡献乘以固定采样预算 K（默认 49），使用 [0,3] 色标，表示相对均匀分配 1/K 的倍数。超限饱和但数值保留，不逐图自动拉伸。基线展示自己的真实 decoder attention 位置与权重，不给它伪造一个光谱门。

图中彩点是采样位置的量，不是分割结果。权重低到看不出颜色差异时，先读取原数值；不要分别拉伸两幅图来制造“更清楚”的差异。

每张图对应一个 NPZ，记录所选查询的坐标、有效性、候选与背景嵌入、背景权重、均值／协方差、有效样本数、目标原型、距离尺度、判别方向、分数、兼容性、门、attention、最终贡献、更新前后查询及最终框／分类 logits。
基线保留最终预测、GT 关联和实际 attention。图例源图一次保存于 `sources/`，全部样本的侧车 JSON 记录原文件路径与 SHA256。保留原数据集和逐轮 checkpoint 可补做其他机制干预。

`population.json` 按对象保留类别、对应分类分数、门均值、贡献总量、背景支持和残差等；固定图例不能用于估计“多少比例对象受益”。群体结论还应区分类别、尺度并保留零贡献与失败对象。

## 训练诊断与轻量评估

按已有 `diagnostics_train_interval` 记录步骤统计：`method_diagnostics.spectral_evidence` 分开普通查询和 DN 查询，包含门值、门低于 0.01 的比例、兼容性、贡献总量、有效背景支持、对角回退和残差范数。统计全部 detach，不改变损失和梯度。

日常评估使用 `diagnostics_eval_records: compact`：每个 batch 保存原始最终查询 logits、原坐标框与最终检测张量；不逐条写数千万条候选 JSON，不计算每层全测试集 AP。主指标仍是同一 ProbIoU 匹配与 AP 积分。`performance.rankNNN.jsonl.gz` 和 `summary.rankNNN.json` 包含前向、后处理、归档、AP 累积耗时。

默认仅计算主指标；真实几何 IoU 分析通过 `--geometric` 追加。需要旧几何匹配轨迹时显式使用 `--details`；其中旧通用诊断的 `final_tp50` 属于几何匹配分析，不等于 MODA 主 ProbIoU 指标。

后处理和机制补采命令统一见 [运行指南](RUN_EXPERIMENTS.md)。这些代码保存证据，不提前保证训练后图形或精度一定支持研究假设。
